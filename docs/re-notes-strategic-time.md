# 战略时钟、绘制与声音关系复核

> 状态：本轮战略时钟重构已完成本地实现及下述限定验证。共享Clock、日历／季节、军团轮询、云对象、接战音画及相关暂停／消息返回均已接线；不等于完整自然战役或实机音色认证。用户要求查清整体关系后用JavaScript＋Canvas实现等效表现，不必照搬DOS硬件限制；不能把观察到“约四响”当固定规则，也不能预设所有分支共用同一时钟。
> 本页维护本次跨模块研究与实现方案；既有详细源为[内核](re-notes-kernel.md)、[音频](re-notes-audio.md)、[行军](re-notes-march-pathfinding.md)。原Web固定表现节拍见[行军表现](march-presentation-fixes.md)，已由本次时序替换，不作为原版证据。

## 2. 已复核的关系图

```text
YNSOUND IRQ0（PIT除数256）
 ├─ 99E bit1允许时B69倒数 → 重装B68 → 03AC音乐（曲内节拍）
 ├─ B6A每16 IRQ → 注册far callback → KI:0356
 │                                  D2C=1，D2D饱和递增至255
 └─ B6B每256 IRQ → 旧INT8／INT1C → SFX后继（独立于B6A）

KI:1BE0战略外循环
  1C1F输入／鼠标采样 → 事件处理
  1C5B: 98A3>=80h才调用1CD0
    1CD0: 98A5暂停延迟门 → 1D0B
      3EFD 据点 → 25A3 军团16槽 → 2459 地图对象32槽
      → 1D8E 日历／时刻进位 → 1DF8速度等待
  1C69: D615 → 1CC9 → D66A（本轮绘图／提交）
```

**实锤范围**：普通外循环每次至多一次战略主更新，随后调用绘制；没有在这里查到Web式“同一显示帧先跑36次主更新再画一次”。这不等于已经证明全部绘制callee耗时、屏幕刷新率或所有模态路径。

### 3.1 音效请求与播放时钟分离（本轮追加原字节复核）

- KI:02F5比较上次ID与新AL；旧ID>=新ID直接到0306，否则INT61 AH0A查busy bit2。030A以AH5请求；相同ID3可重触发，并非同时叠加多个通道。
- COM:017D安装INT1C→06FA；0716调用07CF，07D7递减09EF，到零按09EE调用07E6。07E6从SOUND记录+0D／+0E重新装后继ID／计数，0828先关channel6再写当前记录。此链不读战略CFA。
- `SOUND.DAT`304B，SHA256 `b5624388d1bc8f6bb32aeff1d19b1da4c010d7b5a9682a249f1b807c27f2cdba`。16B记录3=`08080083f6b66f7f0706fc6b3d0d0330`；记录13=`08080080f6b66f7f0700fc6b3d000730`，故3→13等待3个BIOS tick，13→0等待7个BIOS tick。
- COM:08EA B6B初始化0，0943每IRQ byte减一，256 IRQ后经094C跳旧INT8；与B6A的16 IRQ游戏回调不同。BIOS节拍约54.925ms，声音尾段计时不因战略档位缩放；重复请求会重新装同一通道／后继，所以**请求频率随行军轮询变化，但音高／单记录播放时基独立**。实际首tick相位与声音优先级必须保留。
- KI:033B–0348以DS:DX注册0356；COM:02FB–0317写093D far call操作数或换成空回调。不是浏览器RAF的直接等价物。

## 4. 暂停门：本次已确认边界

- `1F7F`调用外部鼠标服务；坐标未变在1FC8 OR 98A3,80h；变化在1FD8置98A5=12、1FDD清98A3高位。1C5B因此跳过当轮战略更新，但仍走绘制。
- 静止后`1CD0`：98A5>1时清D2C／D2D并减98A5；=1且D2D<A0h时，1CF2跳到1D1F直接RET（不是原地忙等），下一外循环继续采样／绘图；达到门槛才清计数与98A5，落入主更新。这里不是单纯“鼠标停后固定1秒”；Web现行1秒hold是已批准产品差异。
- 通知入口`8810→222B`进入独立鼠标／计时等待循环，期间没有调用1D0B；返回在8847写98A5=8。222B以D2D达到255累计十轮后返回，并在226A清D2D／D2C。此为该入口的原控制流，不套用Web已批准的三秒通知政策，也不推广到所有多步对话。
- `1B5A→9946→9FA0`同步进入战术，返回后1B7B恢复战略资源再绘图；战略外层在该调用返回前不迭代。音乐／SFX驱动由中断运行，不因战略外循环等待就自动停止。
- 菜单映射现已从原命中图入口`E453`、分派表和文字闭合：`1C36→59A6→[59D2+2×AL]`左键ID1/2/3/4分别为614A军师条、5E1E势力资源、5A3A小地图、5FAA系统选单；右键`59B7→5A06`相应1/2/3为61B6/5E4C/5AA2关闭，4为RET。前三个打开入口设置98A6的bit0/1/2后RET，外循环仍可运行；不是展开即暂停。Web军师条只能羽扇关闭是另行批准差异。
- 军师ID12→61CA按`(mouseX−18h)/30h`选八项。原字串6181为「進言／人事／財政／編成／軍團／據點／武將／勢力」；6214八word依次`6224/6265/678D/6288/628F/62FB/6366/63BF`。进言、人事、军团、据点先走93E9菜单，编成走6C5E→7663列表，武将75FA、势力78A7；列表共用820E→8412→21E7输入循环。财政6796→21E7，系统5FBE→21E7；均在返回父调用前阻断战略外循环。93E9→9479→036F→0414的044C鼠标轮询同样不调1D0B。列表/据点定位中的1D46只重绘（1D73→D615→1CC9→D66A），不是战略更新。7E1F据点卡片在7E39循环21E7等待右键；6366武将详情经8810后返回列表。这里闭合暂停/绘制边界，不重做每项业务规则或授权更改其Web交互。

### 4.1 季节与日历补核

`9336`按月份表9315选源／目标48B调色组，以CF0（日）传给0A65。表原字节为`333330000001111112222223`，高半字节为源、低半字节为目标，组基址18A4：0春、1夏、2秋、3冬。因此三／六／九／十二月分别3→0、0→1、1→2、2→3，其余月源目标相同。

0A65将日钳到16，逐16色调用EC2E。EC6C把有符号分量差放AH、AL清零，SAR AX四次、乘日、加0080h，取AH：`source + floor((target-source)*min(day,16)/16 + 1/2)`。EC2E按CH／DH／BH顺序左移2位写VGA DAC（不要把文件BH／CH／DH顺序直接命名RGB），返回BH／CH／DH写1964缓存。因此渐变是日历驱动，不是独立动画时钟。

原始资源补核：MZ入口0000→003A→006B→007D置AL=0→007F调用09AF；09B5将文件名`GAMEPAL.BRG`、BX=CS、SI=18A4、CX:AX=AL×C0h、DI=C0h传给E38C→F4DF。F4DF以DOS 3D00打开、4200定位、3F读取。不能直接把EXE文件18A4处的零块当调色数据。`GAMEPAL.BRG`384B，SHA256 `1f0119c75ea5cd333bd3ac75ef92030f93924f011728edc9b1f727c483263708`；默认首192B为四组BRG，每分量0..15。原输出按CH(R)、DH(G)、BH(B)左移2位。现有PNG沿离线导入约定将每分量映射为n×17（不是VGA实机亮度认证）。本轮从原`MMAP.MDL`四平面逐像素解码并配合该BRG，与当前正式编译目录四张atlas逐张65536像素比较，全部一致。

**现代呈现选择（本次JS＋Canvas等效效果范围，非DOS机制）**：保留日期、源／目标和16天边界，使用已绑定PNG的RGB分量线性插值并四舍五入到8-bit；不模拟原0..15分量量化，也不猜测自建游戏PNG的调色板。只生成256×256当日atlas，交回原分块地形和运行地形差分绘制；不改规则地形／小地图配色，不生成16张全幅地图。旧整图资源端口保留画布叠加渐变。资源仍走world所属image／bytes／season端口，await后核所属；App以请求对象区分同季不同日期，防止迟到的旧日图覆盖新日图。

App已有`onHour→score.calendar`和加载时`score.strategy`；本轮核对93D7、9309表并复验，没有添加音乐计时器。加载按实际日期设置渐变；正常运行只在9377对应onHour条件请求，已删除HUD的100ms按月换图。

**月结异步返回补核与修复**：原1DD1写新年月对应day0，1DD4 CALL5358，返回后才1DD7日加一、1DDB小时清零、1DE0小时加一、1DE4子刻归零、1DE9调用9377。因此5358内消息等待期间仍为`新月/day0/hour23/sub8`。本轮再次核5358→538E585F→592C8810→5930归属/人数写回→余将→5391评分／外交／预算／灾害／政策→53C5 RET；消息返回证据复用[消息ABI](re-notes-strategic-message-abi.md)已闭合的8810 near RET，不以UI观察代替。

旧Web虽最终hour1正确，却在onMonthEnd挂起时提前day1/onHour，且过早清sub/hour。现Clock以`_pendingMonthAdvance`保留返回点，通知及余下月结全部返回后才推进day1/hour1/sub0，不重跑月结、军团或RNG。地图对象准备和保存守卫也检查该返回点；通知关闭到下一时钟步之间仍禁存。`onDay`测试钩子同样保留旧hour23/sub8，生产没有onDay业务。Web不保存半完成的DOS调用栈，此为明确工程边界。

## 5. 实施前的Web差异与故障线索（历史快照）

以下描述重构前状态，不代表现行实现；已改项目及证据见§6.1。

- 当前Clock每RAF最多36主更新，而军团连续步仅需16／24更新；60Hz顶速可在两次画面之间提交不止一个道路点。MapView仅保存最后prev→current，无法展示已被后续步覆盖的中间段。**结构风险明确**；实际跳步轨迹还需隔离浏览器记录，不把受控单步三倍速度测试当平滑证明。
- `EngagementPresentation`只在地图RAF观察最终接触集合，以墙钟30ms换帧／20ms请求声音，且结束时stopSound。它与按战略更新缩短的接触窗口不同步；极短接触可能未被任何RAF观察，或仅响一次即取消。需要追App更新顺序与音频生命周期后确定实际路径，不能用延长战斗／凑五响掩盖。
- `WeatherPresentation`用独立100ms动画和120ms指数追赶位置，暂停虽跟随hold，换帧和追赶频率却不随战略更新。与原版timer／dirty关系不同。
- App的实际`main.js:frame`顺序为`syncClock → advanceFrame → engagementFx.update → weatherFx.update → draw`；主更新中途进入战斗／过渡后，接战FX可能直接被enabled门清掉。原生`originalroadmovement.js:wait`目前只写`_engagement`，没有286C对应声音事件输出，无法从最后一次RAF快照恢复中间所有声响请求。这是已定位的接线差异，不是音频资产太慢。
- App另以100ms HUD刷新按月份调用`setSeason`；与9377跨换季月前16天的调色入口不同，需连同季节资源／BGM一起审计，不能仅改Clock常量。
- 上述来自本次代码审阅，不反向证明DOS规则。此前固定五响／独立云动画／三倍速均有历史产品来源；本次用户要求重建整体等效体验，不能只再改几个毫秒常量。

## 6. 现代实现方案（已落实，非DOS硬件复刻）

用户授权用JS＋Canvas实现等效效果，后续明确指定五档提速数值。以下为现行Web调度选择，不把刷新率／预算说成KI原参数：

- 五档墙钟间隔为 **6.5／5.0／4.8／1.8／1.0ms**，按用户给定值保留一位，不按统一倍率换算。撤换初始重构的原计时回调×4／3／2／1与最高档2.083ms策略；原等待是累计门的证据不变，不模拟CPU指令执行耗时。
- 每RAF最多16个主更新，即两次128槽轮转。正常周期2／3的军团动作间隔16／24次主更新，故单帧至多提交一个常规道路步点；卡顿时减速而不是追积压。正常60Hz最高预算由480提高至960主更新/秒，高刷仍受1.0ms档位约束，上限1000更新/秒；实际吞吐受设备负载和hold影响，不承诺所有设备实测翻倍。
- 高速RAF可能跨过接战／天气的中间显示相位；绘制仍采样当前规则相位，不为播全动画延长接战、补播声音或另造时钟。道路逐点提交、六队周期、RNG消费及规则顺序不变；玩家和Trial共用常量，战术速度不变。
- 军团位置沿已提交的prev→current按战略相位插值；变速保留子步相位，暂停不推进表现，不制造新道路／提前移动／额外RNG。不得让将来规则预算充当插值相位。
